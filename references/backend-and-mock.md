# 后端、接口与 Mock 等价

## Goal

复刻可观察契约，而不是猜测参考系统的数据库、微服务或算法。只有用户提供并授权的源码/Schema 才能作为内部实现真值。

## 可信级

- T1：用户拥有的源码、OpenAPI、Schema、迁移和测试。
- T2：获准观察的请求/响应、状态码、公开事件、UI 结果和持久化行为。
- T3：仅能从界面推断；只能实现满足已观察 Scenario 的最小模型，并标记不确定性。

不得把 T2/T3 推断描述为“完全复制了后端或数据库”。

## 契约台账

按业务能力记录：输入、输出、错误、权限、幂等/重复提交、分页/排序/过滤、持久化、异步任务、上传下载、实时更新、时间/时区和恢复行为。敏感字段只记录类型与规则，不保存真实值。

## 实现原则

- 优先保持外部契约稳定，内部结构选择最简单、可测试、可替换的实现。
- 未观察到的行为不要过度建模；为关键不确定性建立 Gap。
- 生产服务不可被测试写入；副作用只能在获准测试环境执行。
- Mock 使用确定性的合成数据，覆盖正常、空、边界、错误、权限和并发/重试场景。
- 上传文件、账户、订单、日志等不得复制真实客户内容。

## 验证与完成

使用契约测试和端到端 Scenario 比较请求语义、响应结构、状态码、错误映射、持久化结果与 UI 状态。完成条件是声明范围内的可观察契约通过，而不是内部表名或架构相似。
