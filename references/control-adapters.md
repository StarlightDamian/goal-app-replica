# 控制适配器与会话边界

## 目标

选择能稳定观察和重放真实状态的最低成本控制通道，同时不抢占用户前台、不混淆参考端与复刻端、不泄露登录信息。

## 能力优先级

按任务需要选择，不机械固定：

1. 平台结构化通道：Web DOM/CDP/Playwright，Android ADB/UIAutomator/Appium，iOS Simulator/XCUITest，桌面可访问性树或应用自动化接口。
2. 浏览器连接或内置浏览器：适合复用项目专用登录态、批量导航与截图。
3. Computer Use/视觉控制：结构化能力不足时补位，适合可见交互，不作为隐藏数据通道。
4. 人工协助：验证码、设备信任、硬件限制或高风险确认。

选择依据是可观察性、稳定性、后台隔离、状态复现和证据质量，而不是工具名称。

## 会话合同

每个控制面记录：项目、side（reference/replica）、身份/角色、profile/device、环境指纹、可写策略、Owner 和最后健康状态。复用登录态前先验证这些字段；不得读取日常浏览器中与项目无关的 profile。

参考端与复刻端使用不同会话/窗口/设备标识。任何自动输入前再次确认 side；参考端默认只读。

## 广度优先使用

拿到 Browser 或 Computer Use 控制权后，优先完成一个有界的探索批次：安全点击、下钻、关键状态、视口与截图落盘。释放控制面后再集中开发；不要在浏览器和编辑器之间按页面高频切换。

## 并行与后台

- 同一浏览器、桌面、模拟器或真机只能有一个 Owner。
- 多项目使用独立 profile、端口、VM/桌面会话、AVD/UDID 和网络路线。
- 后台等级应如实标记：真正 headless/独立桌面、可后台但可能抢焦点、必须前台。
- 工具声称“已连接”不代表可用；先探测导航、树、截图、输入、持久会话和隔离能力。

## 降级与阻塞

结构化通道失败时可降级到视觉控制，但证据等级随之降低。以下情况应记录 blocker，而不是绕过：登录/完整性检测、平台安全限制、不可用的 iOS 构建环境、无法隔离的生产账号、不可逆业务动作、身份或 side 无法确认。

### 失败 Trace 反思与同通道修复

控制动作失败时，只在当前步骤 trace 中执行一个有界 repair slot，不新增持久状态或改写整体策略：

1. 从实际 trace 记录 `channel`、失败动作、最后成功状态、错误/现象和失败后的新观察；只选一个主分类：`timeout | kernel_reset | target_closed | focus_loss | evidence_missing | runtime_defect | site_fault | unknown`。分类必须有 trace 事实支撑；只有同一通道恢复健康后的新观察能直接证明时才记 `site_fault`，工具生命周期故障不得记为站点故障，`runtime_defect` 只表示有直接证据的复刻端运行缺陷。
2. 写一条针对该主分类的最小 repair hypothesis，并写一个能证伪它的检查；每次只做该假设所需的一项最小修复。控制生命周期类故障只修复同一已授权通道内的绑定、目标、焦点、等待边界或证据采集前置条件；确认的 `runtime_defect` 只做最小实现修复并用同一通道复查。不得借反思自由重写指令、大范围实现或访问策略。
3. 每个失败最多执行 **2 次**同通道 repair attempt。每次先做假设要求的最小修复，再重新观察并运行证伪检查；成功、假设被证伪、重复同一失败签名、证据仍缺失或触及安全边界时立即停止。
4. 在步骤 trace 中留下 `classification / facts / hypothesis / falsifier / attempt / outcome`。未取得检查所需证据时结论为 `unknown`，不能报成功；除非用户明确更新授权通道合同，否则禁止静默切换通道，并将仍未恢复的步骤记为 blocker。
