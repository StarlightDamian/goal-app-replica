# 广度优先交付波次

## 目标

用较少的控制面切换和返工完成整个范围，而不是逐页局部最优。默认顺序：

```text
DISCOVERY_SWEEP → FIRST_PASS_BUILD → BATCH_COMPARE
→ CORRECTION_WAVE → BATCH_VERIFY
```

## 原则

- **控制面优先用于探索和留证**：拿到参考浏览器或 Computer Use 后，先排空当前安全探索队列。
- 将按钮点击、页面下钻、弹窗/菜单/错误态和关键视口作为一个发现批次。
- 每次重要状态变化后立即保存截图、公开结构、URL/页面身份、动作与上下文；不要依赖记忆。
- 先完成全范围首轮开发，再处理非阻断的局部视觉误差。
- 只在波次边界统一成对比对；局部截图仅用于开发反馈，不能提前关闭页面。

## 1. `DISCOVERY_SWEEP`

目标是冻结一份足以驱动首轮实现的 Discovery Matrix。至少覆盖：

- 必需页面/流程、入口与返回路径。
- 关键默认态、交互态、空/错/权限态。
- 角色、数据前置条件、视口/设备和环境指纹。
- 每个状态的参考证据与尚未探索的显式缺口。

参考端默认只读；高风险或不可逆动作只记录为阻塞/待授权，不为覆盖率冒险。

退出条件：所有必需范围都有参考证据或明确阻塞，且证据已落盘。

## 2. `FIRST_PASS_BUILD`

目标是让所有必需范围达到可运行的第一版：

1. 环境与全局基础；
2. 页面骨架和共享组件；
3. 页面模块、状态与核心流程；
4. 可观察 API/持久化契约。

首轮不要求 pixel pass。局部测试可以解除构建或结构阻塞，但不得把“单页高度相似”视为波次完成。

退出条件：每个必需页面/流程均已实现或有明确 blocker；批量 QA 任务已依赖全部首轮 Builder。

## 3. `BATCH_COMPARE`

在同一 Scenario 合同下批量采集复刻端，并与未过期参考证据配对。输出：

- 结构、行为、接口和视觉 Gap；
- 跨页面根因簇；
- 影响范围、优先级和建议修正波次。

优先级通常为：环境/基线 → 缺失结构 → 布局与 Token → 字体/资产 → 共享组件 → 局部 raster。

## 4. `CORRECTION_WAVE`

每个波次围绕一组根因和受影响范围组织，而不是围绕一个截图来回调 CSS。修正后做必要的局部回归；整页和跨页回归留到波次边界。

## 5. `BATCH_VERIFY`

由独立 QA 重新采集或重算关键证据。通过则关闭已验证 Gap；失败则保留 Gap 并生成下一波次。accepted deviation 必须由用户明确批准且可追踪。

## 允许打断波次的情形

仅限：P0 全局阻塞、错误/失效基线、构建或测试链断裂、安全问题、不可恢复的上下文漂移，或用户明确把范围限定为单页。
